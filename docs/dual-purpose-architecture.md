# Kai legal and Android assistant architecture

## Reuse what the fork has

- **Application**: The shared Kotlin/Compose app owns the composer, settings, tool orchestration, model adapters, and scheduling. The Android app hosts the PRoot runtime and includes the existing Build workspace and attachment ingestion.
- **Providers and tools**: Reuse configured provider instances (including OpenRouter, NVIDIA, and OpenAI-compatible endpoints) rather than building a second chat client. The app already supports remote MCP, GitHub Actions, and a sandbox shell.
- **Builds**: Use the checked-in arm64 debug workflow. Independently verify the job conclusions and match the APK and commit SHA before installation. The existing sandbox distribution selector does not offer Ubuntu; validate any Ubuntu rootfs option on an actual Android device before changing the default.
- **First implementation slice**: Research and Draft composer modes, visibly unverified Draft replies, compact Objective recovery, a checkpoint mirror, and off-device desktop tests alongside the APK build. No new legal vendor credentials or matter data are required for this slice.

## Next implementation slices

1. **Project identity and routing**. Add per-project mode and provider profiles keyed by `instanceId`. Expose user-selected routes for reasoning (Plan/Draft), low latency (Research/Objective/OCR cleanup), vision (OCR), and versioned embedding/reranking. Validate capabilities at startup. Never fall back from a local-only or confidential project to a hosted provider without consent.
2. **Isolated library**. Store immutable originals, complete extracted text, and a manifest containing source hash, page/line spans, and extractor version. Separate matter, law and code collections at the storage and tool layers. Bind allowed collection IDs from the project configuration instead of accepting arbitrary collection IDs from the model. Store OCR text and photo descriptions as distinct evidence types. Index structural chunks in FTS5 (BM25) and a versioned vector index; fuse ranks with RRF. Reserve a separate normalized identifier channel for exact citation, docket, Bates and error-code lookup before fusion and result truncation.
3. **Legal release gate**. Parse authorities and short forms with eyecite, resolve editions and pinpoints to actual opinion text, and preserve majority/concurrence/dissent boundaries. Check quotes against the cited span; use fuzzy matches to locate candidates, not to approve altered quotes or omissions. Treat existence, quote fidelity, precedential status, and treatment as separate fields. CourtListener and the local index are evidence sources, not proof of current good law; unknown treatment must stay unresolved pending authoritative review. Store any fetched opinion with provenance before embedding. Bind a `cite_check` report to the draft hash and invalidate it after edits. Block verified export, not just a chat message, until the report passes.
4. **Export and vendor fallback**. Build and verify the local renderer first. Make the requested remote vendor adapters optional and confirm that the relevant endpoints and OAuth scopes exist before releasing documents to them. Render court-specific formatting from a profile, generate the Table of Authorities from verified citation data, and require human review of caption, pagination, service information, and applicable court rules. Never auto-file or auto-serve.
5. **Permission and checkpoint broker**. For managed Build worktrees, restrict mutations to validated patch/search-and-replace calls. Take a recoverable checkpoint of explicitly in-scope changes before applying each patch; refuse writes if the checkpoint cannot be made. Keep checkpoint refs local; never stage matter files, credentials or unrelated user edits. Do not claim enforcement while an unrestricted shell or another file-write path can bypass the broker. Bind remote CI dispatch permissions to a repository/workflow/ref allowlist and preserve the run ID and SHA before retrying.
6. **Durable Objective runs**. Add typed tool-approval state, elapsed-time and spend budgets, safe cancellation between actions, and a durable action journal with idempotency keys for remote writes. Resume by reconciling the journal and workspace before repeating a side effect. On Android, test restart and process death explicitly: a persistent checkpoint does not imply the scheduler can execute while the OS has stopped the app.
